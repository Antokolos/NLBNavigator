## Итоговая оценка

Ревью Claude Code очень сильное и практически полезное. Я согласен с его главным выводом: текущий успешный CI run — это подтверждение работоспособности сборки, запуска обоих приложений и базовой автоматизации, но **не достоверное подтверждение того, что INSTEAD перешёл ко второй порции текста**.

Самое важное — перестать считать «новая запись в trace появилась» доказательством того, что ожидаемая команда изменила нужное состояние. Нужна явная причинная цепочка:

`action -> observed input event -> resulting semantic state -> screenshot`

Разделяем три слоя: корректность доставки действия (input/automation), совпадение логического состояния (semantic/state) и совпадение представления (visual).

## 1. Что подтверждаю из ответа Claude

### 1.1. INSTEAD: `iface.fmt` не является источником видимой VN-порции — P0

Согласен полностью. Текущий `instead_trace.lua` оборачивает только `iface.fmt`, а при `inv` подставляет `last_story_rendered`. Это сохраняет контекст страницы, но делает проверку второй порции ложноположительной: ожидаемая фраза уже есть в полном тексте сцены.

В `run_route.py` выбирается последняя новая запись trace после действия. Это не гарантирует, что запись представляет результат действия: после клика могут появиться служебные `way`/`inv`, но не новая запись сцены.

Рекомендация Claude оборачивать внешний `iface.cmd` после загрузки экспортных модулей — правильное направление. Для VN-порций это должно стать первичным источником текста, фактически возвращённого пагинатором. `iface.fmt` следует оставить дополнительным источником для STANDARD и диагностики частей форматирования, но не подменять им VN display result.

Дополнение к предложенному коду: записывать sequence number, оригинальную команду и аргументы, тип записи (`scene`, `inventory`, `timer`, `other`), фактический строковый результат `iface.cmd`, identity текущей страницы/комнаты, тип экрана, paginator position, `_last` и интересующие игровые переменные. Сохранять все return values `iface.cmd` прозрачно, включая число/порядок значений и nil в середине. Обёртку возврата стоит покрыть небольшим Lua-тестом.

### 1.2. UUID и экран вариантов

Согласен. Для INSTEAD нужно различать логическую страницу, текущую комнату/виртуальную комнату и UI state: `page`, `choices`, `menu`, `external`, `finished`. Комната `…_choices` не должна считаться новой story page, но нельзя терять факт открытого экрана вариантов.

Промежуточные комнаты ссылок и модулей нужно фиксировать как события перехода, а затем нормализовывать к конечной логической странице для сравнения checkpoint. Не отбрасывать их бесследно: они объясняют путь к состоянию.

### 1.3. Позиция пагинатора и фон

Согласен с предложенными источниками при условии read-only доступа. `paginator._page`, `paginator._last`, `game._realdisp`, `game._lastdisp` дают более точную картину, чем вывод номера порции из скриншота. Сохранять индекс текущей порции, число порций, видимый текст и флаг продолжения; явно определить 0-based/1-based нумерацию.

`vn._bg` предпочтительнее повторного вызова `location:bgimg()`: наблюдатель не должен повторно исполнять потенциально time-dependent код книги. Смысл приватных полей следует закрепить regression test на wolfman и документировать версию INSTEAD/export API.

### 1.4. State snapshot в NLBNavigator — P1

`[screen]` и `--log` недостаточны. Поддерживаю read-only snapshot из `PlayerEngine::screen()` / `ScreenModel`, `GameScreen` (текущая порция, число порций, `m_showChoices`, scroll) и `PlayerContext` (переменные). Существующий сериализатор reference player следует переиспользовать как источник схемы и семантики.

Предлагаю версионируемый JSONL: одна запись после каждой script-команды, `schema_version`, `step_id`, `command_index`, `command`, `command_ok`, `page_id`, `screen_kind`, `portion_index`, `portion_count`, `more_portions`, `visible_text`, choices с порядком/enabled, inventory/scene objects, выбранные story variables, background/image key и revision/session identifiers. Не писать snapshot на каждый animation frame.

## 2. Дополнительные проблемы, найденные в текущем коде

### 2.1. Текст NLBNavigator проверяется по всему логу, а не по checkpoint — P0

В `validate_run()` `text_contains` ищется в полном `playthrough.log`. Это не доказывает, что текст был на экране в момент конкретного screenshot: старый текст, текст следующей страницы или реакция могут удовлетворить проверку не на том шаге. После добавления state snapshot проверять `visible_text` из записи с точным `step_id`/`command_index`, а лог оставить диагностическим артефактом.

### 2.2. Сопоставление INSTEAD checkpoint с trace слишком слабое — P0

`run_instead()` берёт `latest_trace[-1]`, если число записей выросло. Нет идентификатора команды, породившей запись, привязки к действию маршрута, проверки ожидаемого input event и ожидания stable state. Нужно вести sequence cursor до действия, затем ждать новые события и выбирать запись по типу/команде. Для `advance` критерием успеха должен быть paginator advance или переход в choices/page, а не просто новая строка trace.

### 2.3. Выполнение script-команд нужно подтверждать явно — P1

На каждую команду сценария требуется ровно одно подтверждение выполнения и одна запись состояния. Стоит ввести структурированный протокол с command index и явным status. Ошибка команды должна приводить к failure даже при exit code 0 приложения.

### 2.4. Нормализация текста не должна скрывать ошибки

Хранить raw text и normalized text раздельно и прикладывать diff. Нормализовать только документированные преобразования. Не сводить безусловно все кавычки, пунктуацию и переводы строк к пробелам: `^`/newline могут разделять абзацы и VN-порции.

### 2.5. Изоляция сохранений — P1

Поддерживаю рекомендацию Claude запускать INSTEAD с `-appdata <run-specific-dir>`: HOME/XDG, по его локальному эксперименту на INSTEAD 3.3.2 под root, не перенаправили `/root/.instead`. Отдельно изолировать HOME/XDG для NLBNavigator. Не считать `-noautosave` заменой изоляции профиля.

### 2.6. Временная модификация `main.lua`

Текущий `finally` восстанавливает файл при обычных исключениях, но не гарантирует восстановление при SIGKILL/runner crash/cancel. Лучше не менять checkout экспорта: подготовить изолированную копию/overlay с тестовым `main.lua`. Symlink-схему сначала проверить экспериментом на том, как INSTEAD разрешает game path и загружает модули.

### 2.7. Центр экрана не универсальная click-координата — P1

Center-screen click может попасть по gobj, варианту или интерактивной кнопке. Semantic actions должны выбирать цель по имени/идентификатору или hitbox. Raw click должен задавать явную координату и использоваться отдельно для проверки мышиного ввода.

## 3. Модель действий

Поддерживаю семантический слой поверх raw input. Минимальный словарь: `capture`, `advance`, `choose`, `click`, `object`, `inspect`, `use`, `menu`, `set`, `start`, `wait_until`.

`set`/`start` — только test setup actions, явно помеченные как вмешательство в состояние. `wait_until` должен опрашивать read-only состояние без `refresh()`/`afterCommand()`/побочных эффектов, иметь timeout и возвращать отдельный `timeout`. Для smoke-test настоящего Space/click оставить отдельные raw-input маршруты.

## 4. Ожидание и экран вариантов

В `SdlPlayer::scriptCommand()` команды проходят через общий post-command блок `m_session->refresh(); m_screen->afterCommand()`, кроме оговорённых input/render-команд. Поэтому `wait:` может сбросить `m_showChoices`. `shot:` исключён из этого блока — между последним advance/choice action и `shot:` нельзя вставлять `wait:`.

Не использовать произвольный sleep как синхронизацию. `wait_until` должен читать состояние без вызова обновлений с побочными эффектами. В INSTEAD дождаться `vn.stopped and not vn.bg_changing`; завершение dissolve и продвижение текста — разные состояния.

## 5. Подложка VN

Подтверждаю описанное Claude расхождение: INSTEAD использует центральную полупрозрачную панель и боковые `fl.png`/`fr.png`; NLBNavigator в `GameScreen::renderVisualNovel()` сейчас заливает широкую полосу единым цветом `{0,0,0,110}`. Это реальное отличие композиции темы, а не сглаживание.

Перед исправлением проверить координаты/scale/alpha на разных размерах окна и `textScale > 1`; использовать `ScreenTheme::frameLeft`/`frameRight`; не растягивать края произвольно; проверить темы без этих файлов; отдельно проверить inventory panel (у неё другая заливка). Добавить visual regression по маскам центра и боковых краёв. Исправление — отдельный PR в `main`, не в тестовую ветку.
