## 1. Модель сравнения

**1.1. Общий маршрут — правильная основа, но с семантическими действиями.** Ввод в движках
по-разному отображается на действия игры. Поэтому шаги стоит описывать смыслом, а адаптер
каждого движка переводит их в ввод:
- `advance` — следующая порция;
- `choose: {text | index}` — выбор варианта;
- `object: label` — щелчок по объекту;
- `use: item > target` — применить предмет;
- `menu: …` — пункт меню.

Сырые `key`/`click` оставить для проверки самого ввода.

Различия ввода **[факт]**:
- INSTEAD, VN-страница (`paginator.lua`, `paginatorKbd` / `paginatorClick`):
  - пробел и щелчок мимо графических объектов — следующая порция;
  - на последней порции оба ведут в комнату вариантов (`walk_to`);
  - если идёт эффект (`dissolve`), первый пробел только завершает его (`if vn:finish() then
    return end`) и порцию не листает;
  - щелчок в области инвентаря игнорируется;
  - щелчок по gobj уходит объекту.
- INSTEAD, экран вариантов (`vn_choices`): пагинатор выключен (`enter` → `paginator:turnoff()`),
  пробел ничего не делает. Выбор — только щелчком по ссылке.
- nlb_sdl (`GameScreen::key` / `click`):
  - пробел и щелчок по фону листают порции; на последней порции открывается экран вариантов;
  - на экране вариантов работают щелчок и цифры 1–9 (нумерация — решение владельца).
  - В сценарии `--script` есть смысловые команды: `c:<начало текста варианта>`,
    `clickchoice:N`, `o:<объект>`, `u:<предмет>><цель>`, `clickobj:`, `start:<pageId>`,
    `set:var=expr` (`SdlPlayer::scriptCommand`).

**1.2. Надёжные точки эквивалентности**, по убыванию надёжности:
1. **UUID страницы.** Экспорт называет комнату `v_<uuid с _>`, в NLB это `PlayerEngine::screen().pageId` **[факт]**.
2. **Переменные книги.** В INSTEAD это глобальные `_<имя>`.
3. **Номер и текст видимой порции.**
4. **Список доступных вариантов** (текст и порядок).
5. **Инвентарь** (подписи).
6. **Фон страницы.**

Пиксели — последними.

**1.3. Законные различия идентификаторов и текста** **[факт]**:
- Комната вариантов в INSTEAD — `v_<uuid>_choices`, в nlb_sdl это та же страница с открытым
  экраном вариантов. `nlb:curloc()` на экране вариантов указывает на страницу: `walk()` в
  `walk_to` не меняет `_curloc`. `here()` — это комната `…_choices`.
- Ссылки STANDARD/xact — временные комнаты `v_<id ссылки>` с `enter → nlbwalk`. Это переход, не
  страница: в трассе они видны как промежуточные записи.
- Переходы в модуль и из модуля (`Traverse` / `Return`) — тоже сгенерированные комнаты.
- Фон: экспорт по пресету меняет PNG на JPG, имя без расширения остаётся (у вас это учтено:
  `image_suffix` / `instead_background_suffix`). Стоит сравнивать имя без расширения.
- Текст. Экспорт выводит исходный текст через модули `dash` / `quotes` при отрисовке, а
  `--log` nlb_sdl пишет исходный текст. Перед сравнением нормализовать:
  - `--` → `—`;
  - кавычки;
  - пробелы подряд → один (INSTEAD их схлопывает, `get_word`);
  - `^` и `\n` → перевод строки.
- Задержки и эффекты различаются (`dissolve` в INSTEAD), поэтому сравнивать состояние после
  успокоения, а не через фиксированное время (п. 4.3).

**1.4. Регрессия или допустимое различие.** Регрессия:
- другая страница, другой набор или порядок вариантов, другие значения переменных или
  инвентаря;
- другой текст порции (после нормализации);
- другое число порций;
- переход, которого нет в другом движке;
- пропавший или лишний фон.

Осознанные решения NLBNavigator — не регрессии (записаны в CLAUDE.md обоих репозиториев):
- **Экран вариантов:** номера «1.», крупнее шрифт, выравнивание влево.
- **Ответ на действие** виден и после автоперехода — INSTEAD его теряет. Не показывается только
  ответ, совпадающий с текстом новой страницы.
- **Всплывающее «Получено достижение: …»** у nlb_sdl; INSTEAD лишь пишет в лог
  `Setting achievement`.
- **Окно текста VN на 1 px ниже** — округление координат.

Ведите эти различия в файле допусков (п. 5.8) с обоснованием и ссылкой на решение.

## 2. Инструментирование INSTEAD (`instead_trace.lua`)

**2.1. Главная проблема: `iface.fmt` не видит листание порций.** **[факт, по исходникам]**
Путь пробела:
1. `input.key` (kbd.lua) возвращает `'user_kbd'`.
2. Дальше `iface.cmd('user_kbd')`, затем `game.action` и `paginatorKbd`.
3. `paginatorKbd` возвращает `game._realdisp` с `RAW_TEXT = true`.
4. `iface.cmd` (stead.lua, ветка `if stead.rawget(_G,'RAW_TEXT')`) возвращает текст **до**
   вызова `self:fmt`.
5. Внешний хук `paginatorIfaceCmd` режет его на порцию (`text_page`).

Итог: при листании `iface.fmt` не вызывается вовсе.

Единственный вызов `fmt` после щелчка в шаге `opening-next-portion` — `cmd == 'inv'` (обновление
окна инвентаря). Ваш адаптер подставляет в него `last_story_rendered` — **полный текст сцены
со всеми порциями** с прошлого шага. Поэтому `instead_text_contains: «Интересно, сколько я тут
валяюсь»` проходит, даже если щелчок не сработал: эта фраза есть в полном тексте страницы с
шага `opening`.

Как исправить — наблюдать **внешний `iface.cmd`** (адаптер грузится после модулей, поэтому
его обёртка внешняя по отношению к `paginatorIfaceCmd`). Его строковый результат — ровно то, что
INSTEAD выводит в окно сцены.

```lua
local original_cmd = iface.cmd
iface.cmd = function(self, cmd, ...)
    local r, v = original_cmd(self, cmd, ...)
    if cmd ~= 'inv' and type(r) == 'string' then
        -- r — видимая порция (или вся сцена STANDARD); пустая строка — экран без текста
        write_record{ kind = 'scene', cmd = cmd, shown = r, ... }
    end
    return r, v
end
```

- Записывать каждый вызов с полем `cmd`: `look`, `user_kbd`, `click …`, `act …`, `use …`,
  `go …`, `inv`, `way`. `user_timer` с результатом `nil` пропускать.
- На контрольной точке брать последнюю запись **сцены** (`cmd ~= 'inv'`), появившуюся после
  действия. Если её нет — это сбой ввода, а не расхождение движков.
- Отдельно, из той же обёртки или из `instead.get_inv` (`ext/gui.lua`), писать строку
  инвентаря. Её видит игрок: после фикса `paginator.lua` (`instead-am_i_a_monster_vn#1`)
  инвентарь на VN-страницах отображается.

Проверено экспериментом **[факт]**. INSTEAD 3.3.2, тот же экспорт, ваш `instead_trace.lua`
плюс журнал внешнего `iface.cmd`; пробел, затем щелчок по центру. Последовательность `iface.cmd`:

```
look                       paginator._page=1    shown=« »
user_kbd                   _page=232  _last=false  shown=«Вы очнулись лежащим…»   ← fmt вызван (вход на страницу)
way / inv                  shown=«» / «Волчность: 0    Жизнь: 3»
click true,1,959,562       _page=596  _last=false  shown=«“Интересно, сколько я тут валяюсь…»  ← fmt НЕ вызван
way / inv
user_timer (каждые ~20 мс) shown=nil
```

В вашей трассе после щелчка появились только записи `way` и `inv`. В поле `rendered` у `inv`
лежит `last_story_rendered` длиной 2724 байта — весь текст страницы. Отсюда ещё две детали:
- щелчок приходит командой `click true,1,<x>,<y>`, а не `user_click`;
- `user_timer` идёт непрерывно и возвращает `nil`.

`iface.fmt` оставьте только как источник частей сцены (`room_text`, `action_text`, `objects_text`)
для страниц STANDARD. Там пагинатор выключен, и `fmt` вызывается на каждое действие.

**2.2. UUID страницы.** Поля `nlbid` у комнат нет — в `module_ru.lua` оно есть только у двух
объектов **[факт]**. Канонического API тоже нет: `stead.nameof(room)` вернёт `nam` («Am I a
Monster?»), а не имя переменной. Поиск по `_G` работает, но лучше:
- построить обратную таблицу один раз при загрузке адаптера:
  `for k, v in pairs(_G) do if type(v) == 'table' then id_of[v] = k end end`, разобрать
  `^v_(uuid)$` и `^v_(uuid)_choices$` → `page_id` и `screen = 'choices'`;
- брать `nlb:curloc()` (страница) **и** `here()` (комната или экран вариантов) — разные поля;
- `main` — псевдоним стартовой комнаты: в экспорте `main, v_f7cb… = room{…}, vnr{…}`, то есть
  это две разные таблицы. `main` при входе делает `nlbwalk` в `v_f7cb…`.

**2.3. Позиция пагинатора.** Есть **[факт, paginator.lua]**:
- `paginator._page` — байтовое смещение начала следующей порции в `game._realdisp`;
- `paginator._last` — показана последняя порция;
- `game._realdisp` — весь текст сцены;
- `game._lastdisp` — последняя выданная порция.

Номер порции = число вхождений `paginator.delim` (`'\n[ \t]*\n'` в main.lua экспорта) в
`game._realdisp:sub(1, paginator._page - 1)`. Число порций — по всему тексту. «Осталось ещё» =
`not paginator._last`. Читать в обёртке `iface.cmd` после вызова оригинала.

**2.4. Фон, объекты, инвентарь, переменные — без влияния на игру:**
- **Фон.** `vn._bg` — путь, который реально стоит фоном (`vn:set_bg` пишет `s._bg = picture`)
  **[факт]**. Это лучше, чем вызывать `location.bgimg`: `bgimg` у таймерных страниц зависит от
  `curloc().time`, и вызов в неудачный момент даст другой кадр.
- **Варианты.** На экране вариантов это объекты комнаты `here()` (`objs(here())`). Текст —
  `stead.call(o, 'nam')` или `disp`. Доступность — `not isDisabled(o)`. **[гипотеза]**: точный
  состав (xact или объекты) проверить на одной странице дампом `objs()`.
- **Инвентарь.** `inv()` и `stead.call(o, 'disp')`, либо готовая строка `instead.get_inv(true)`.
  Оборачивать `instead.get_inv` нельзя: она `stead.cacheable` — её можно только вызывать.
- **Переменные.** Все глобальные `^_%a[%w_]*$` с типом number, string или boolean, кроме
  служебных экспорта: `_vl_*`, `_mytimer`, `_export_lang`, `_tagsArg`, `_room` и т. п.
  Сопоставлять с переменными книги NLB (п. 3).
- Только читать: ничего не вызывать, кроме `stead.call(o, 'disp' / 'nam')` — это чистые функции
  экспорта.

**2.5. Пропуски и дубли.** Помимо п. 2.1:
- `user_timer` комнат с `timer` (у wolfman их нет; во «Фронтире» заставка — 25 раз в секунду)
  даст поток записей — фильтровать по `cmd`;
- `inv` вызывается после каждой команды — это не сцена;
- в момент входа на страницу одна команда может дать запись `look` с полным текстом и следом
  запись с первой порцией. Брать последнюю.

**2.6. Порядок загрузки.** Адаптер дописан в конец `main.lua` (= копия `module_ru.lua`) и
выполняется при загрузке файла **после** `require` модулей. Хуки `paginator.lua` на
`iface.cmd`/`iface.fmt` к этому моменту уже стоят, поэтому обёртка внешняя — это правильно
**[факт]**.

`init()` экспорта выполняется позже, при старте игры. Не обращайтесь из тела адаптера к тому,
что создаёт `init()`: к переменным книги (`initializeVariables()`) и `vn:scene`. Читать — только
внутри обёрток.

Подмена `main.lua` на `module_ru.lua` корректна: обёртка `main.lua` — это меню языков, а
`module_ru.lua` — полный экспорт с `_export_lang = 'ru'` в своём `init()`.

Две мелочи:
- `os.time()` — секунды; лучше `stead.ticks()` (миллисекунды).
- Правка `main.lua` прямо в `test-data`, с восстановлением в `finally`, оставит испорченную
  копию, если процесс убьют. Надёжнее временный каталог: ссылки на всё, кроме `main.lua`, и
  настоящий `main.lua`. Писать в каталог игры INSTEAD всё равно разрешит.

## 4. Ввод и маршруты

**4.1. Ловушка nlb_sdl: `wait:` между нажатием и `shot:`** **[факт, записано в CLAUDE.md
NLBNavigator]**. `wait:` вызывает `Session::refresh()` и `GameScreen::afterCommand()`, а это
сбрасывает открытый экран вариантов (`m_showChoices`). `script_for_nlbnavigator` всегда пишет
`key → wait:settle_ms → shot`. На первом же шаге «последняя порция → экран вариантов» снимок
покажет страницу без вариантов.

Как исправить: для шагов, которые должны открыть экран вариантов (или для всех шагов
`advance`), писать `shot` сразу после действия. Задержку для анимаций давать до действия, а не
после. Либо добавить в nlb_sdl команду ожидания без refresh — это небольшая правка
`SdlPlayer::scriptCommand`, могу сделать.

**4.2. Чем листать.**
- Основной способ — пробел, нажатием и отпусканием с паузой, как у вас. Мой опыт: `xdotool key
  space` (одним вызовом) INSTEAD 3.3.2 под Xvfb иногда не замечает; ваш keydown/keyup это
  обходит.
- Щелчок по центру небезопасен:
  - на страницах с gobj — кнопки «Отменить квест» в «Шапочке», свитки навыков в
    barbarian_caves_demo, спрайты с подписями;
  - на экране вариантов (окно `get_choices_coords`: x 20–80 %, y 25–75 % экрана) центр может
    попасть в вариант.
  Для проверки щелчка выбирайте точку в полосе текста VN, вне gobj — например, середину полосы
  текста по `theme.win.geom` (y ≈ 838–1042 из 1080 у wolfman).
- Пробел и щелчок стоит проверять раздельно, коротким маршрутом на одной странице; длинные
  маршруты вести пробелом.

**4.3. Выборы, ссылки, инвентарь, меню.**
- **nlb_sdl:** смысловые команды `c:`, `u:`, `o:`, `clickchoice:N`.
- **INSTEAD:**
  - Щелчок по варианту — по координатам. Lua позиции ссылок не знает **[факт]**. Практичный
    способ, которым я пользовался: в окне вариантов найти полосы строк цвета ссылки (`#00FF00`
    у темы NLB) и щёлкнуть в центр N-й полосы. Это надёжно для экрана вариантов VN.
  - Объекты (gobj) — по геометрии из трассы: `vn:test_click` знает прямоугольники эффектов,
    `vn._effects[i].last_rct` **[гипотеза]**.
  - Готовность ловить по трассе, а не по таймеру: ждать, пока `vn.stopped and not
    vn.bg_changing` и в трассе появится новая запись сцены. Фиксированный `settle_ms` оставить
    как верхний предел.

## 5. Что сравнивать

1. **Страница и переход:** строгое равенство UUID на каждой контрольной точке, плюс экран
   (`page` / `choices`).
2. **Текст:** строгое равенство нормализованного текста видимой порции, номера порции и числа
   порций. Порции режутся по одному правилу (`VNSTEADExportManager.getPreprocessedChunks`).
3. **Варианты:** строгое равенство списка (текст после нормализации, порядок) и
   доступности. Отображение (номера, шрифт) — допуск.
4. **Переменные и инвентарь:** строгое равенство значений. Инвентарь — подписи после
   схлопывания пробелов.
5. **Фон:** имя файла без расширения.
6. **Звук:** **[гипотеза]** — в INSTEAD можно обернуть `set_music` / `add_sound` и писать имена
   в трассу; в nlb_sdl — события `AudioDirector`. Сравнивать порядок имён, не время.
7. **Изображение:** только после совпадения состояния:
   - маски областей — полоса текста, окно инвентаря, кнопка меню, gobj;
   - метрика по области — средняя ошибка / SSIM, с порогом на структуру, а не на сглаживание.
   - Отдельная проверка геометрии: bbox текста в полосе, число строк, левый край первой строки.
     Это ловит реальные регрессии раскладки: сдвиги, лишние переносы, другую высоту строки.
     Перенос и шаг строк у wolfman сейчас совпадают с INSTEAD до пикселя.
8. **Допуски** — файл `tests/differential/expected-differences.json`:
   `{id, область или поле, описание, решение со ссылкой (PR / CLAUDE.md)}`. Отчёт отмечает,
   какой допуск сработал.

**Подложка текста (вопрос про градиент)** **[факт, vn.lua `textbg` / `undertext`]**. INSTEAD на
VN-странице рисует под окном текста три части:
- центр — `gr:box(w + 2·pad, h + 2·pad, 'black', bgalpha = 127)` от `win.x − pad` до
  `win.x + win.w + pad` (pad = `textpad` = 8);
- слева `gfx/fl.png`, справа `gfx/fr.png` темы — 240×220, чёрные с альфой 0 → 127 и 127 → 0.
  Ширина берётся из файла (`vn:auto_geom` передаёт `wf` = ширине `fl.png`), так что края уходят
  в прозрачность.
- Окно инвентаря — сплошной чёрный `gr:box(inv.w, inv.h)`.

NLBNavigator (`GameScreen::renderVisualNovel`) сейчас заливает всю ширину сплошным
`{0,0,0,110}`. Альфа и края отличаются — это настоящее расхождение темы. Правильное место —
`renderVisualNovel`: центр с альфой 127 и картинки `ScreenTheme::frameLeft` / `frameRight`
(поля уже читаются из темы). Исправлю в отдельном PR.
