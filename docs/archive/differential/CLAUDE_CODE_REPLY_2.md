### Снимок состояния (#30)

Формат — `docs/state-log.md` в этом PR. Основные поля записи:

```json
{"schema":1,"index":23,"command":"key:space","ok":true,
 "pageId":"f12432d9-…","screen":"choices",
 "portion":{"index":9,"count":10,"more":false,"visible":[{"runs":[{"kind":"Plain","text":"Надо бежать! …"}]}]},
 "variables":{"wolfiness":0,"hp":3},
 "model":{ …ScreenModel… }}
```

- Строка с `index` 0 — состояние до первой команды. Дальше по одной строке на каждую команду
  сценария (пустые строки и `#` не считаются). Номер `index` совпадает с номером команды в
  сгенерированном `route.script`. Если раннер ставит один `shot:` на шаг маршрута, привязка
  «шаг → запись» — по `command == "shot:…"`.
- `screen`: `page`, `choices`, `message` (конец игры, внешняя игра, ошибка) или `finished`.
- `portion` — только в режиме экрана вариантов VN. В STANDARD и при вариантах в тексте
  `count = 0`. Нумерация с 0.
- `variables` — только из `--state-vars` (allowlist). Имена — как в книге, без `_` экспорта:
  `wolfiness` ↔ `_wolfiness` в INSTEAD. `*` — все переменные, для отладки.
- `model` — `ScreenModel` тем же сериализатором, что эталон модели экрана NLB
  (`tools/player-reference/screen/harness.cpp`, теперь `nlb/presentation/ScreenModelJson.h`).
- Текст — исходный текст книги: `--` и прямые кавычки. Экран и INSTEAD показывают «—» и
  «ёлочки». Это документированная нормализация, сырой текст остаётся в снимке.
- Снимок только читает состояние: без refresh и перерисовки. По умолчанию выключен.

Схему можно поправить до слияния #30, если вам нужны другие имена или поля. Скажите — внесу.

**`settle:<мс>`** — ответ на ваш п. 4. Это ожидание как у `wait:`: время идёт, анимации
доигрывают. Но без `Session::refresh` / `GameScreen::afterCommand`, поэтому экран вариантов
остаётся открытым. Проверено: пробел на последней порции → `settle:800` → `shot:` даёт снимок с
вариантами и `screen = "choices"`.

Для `script_for_nlbnavigator` предлагаю:
- `settle:` вместо `wait:` везде, где ожидание стоит между действием и `shot:`;
- `wait:` оставить там, где нужно именно обновление — после `set:` / `start:`.

Ожидания по условию (`wait_until`) в nlb_sdl пока нет. Сценарий выполняется синхронно: после
`key:` / `c:` состояние уже новое, ждать стоит только анимации, и для этого хватает `settle:`.

## Соответствие полей трассы INSTEAD

Чтобы сравнивать попарно, удобно, чтобы адаптер писал те же поля:

| state-log NLBNavigator | INSTEAD (внешний `iface.cmd`, только чтение) |
|---|---|
| `pageId` | `nlb:curloc()` → обратная таблица `v_<uuid>` (составить один раз) |
| `screen = choices` | `here()._is_vn_choices` (комната `v_<uuid>_choices`) |
| `portion.visible` | строковый результат внешнего `iface.cmd` при `cmd ~= 'inv'` |
| `portion.index` / `count` | число `paginator.delim` в `game._realdisp` до `paginator._page` / во всём тексте |
| `portion.more` | `not paginator._last` |
| `variables.<имя>` | глобальная `_<имя>` |
| `model.inventory[].label` | `instead.get_inv(true)` или `stead.call(o, 'disp')` для `inv()` |
| `model.pageImage` | `vn._bg` (без расширения: PNG → JPG по пресету) |
