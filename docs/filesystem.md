# Файловая система плеера

Всё, что ядро плеера читает и пишет во время игры, идёт через `IFileSystem`
(`Source/NLBCore/Public/nlb/util/FileUtils.h`):

- книга — каталог или пакет `.nlbpack` (пакет читается с произвольного места, `openRead`, —
  большие картинки и звук не грузятся в память целиком);
- сохранения (атомарно: временный файл и переименование), достижения, `settings.ini`;
- журнал прохождения и журнал площадок (поток `FileUtils::openWriteStream`).

По умолчанию — обычная файловая система (WinAPI с длинными путями / POSIX). Фронтенд может
подставить свою до открытия книги: `FileUtils::setFileSystem(...)`; `makeNativeFileSystem()` — если
своей нужно делегировать часть путей обычной.

**Unreal** (`NLBPlayer/Private/NLBUnrealFileSystem.cpp`) ставит свою при загрузке модуля: через
`IPlatformFile` движка — так же, как сам движок, на ПК, Android (APK/OBB), Quest и консолях, где
данные игры лежат в образе, а сохранения — в хранилище платформы.

Смонтированный пакет книги (`BookPack::mount`) — слой над файловой системой: пути внутри него
читаются из пакета.

Мимо `IFileSystem` пишут только инструменты, а не плеер: упаковка `nlb_main pack`
(`BookPack::write`), сохранение книги и экспорт ресурсов в коде, перенесённом из редактора
(`FileManipulator`, `ResourceManager`, `VariableImpl`).
