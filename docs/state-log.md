# Снимок состояния для тестов: `nlb_sdl --state-log`

Для дифференциальных тестов с INSTEAD (`tests/differential`, ветка `ci/nlb-sdl-wolfman`) и
других автоматических проверок nlb_sdl может писать состояние игры после каждой команды
сценария `--script`. Снимок только читает состояние: ничего не обновляет и не перерисовывает,
по умолчанию выключен.

```
nlb_sdl <книга> vn --script route.script --state-log state.jsonl --state-vars wolfiness,hp
```

- `--state-log <файл>` — JSON Lines: одна строка до первой команды (`index` = 0) и по одной
  после каждой команды сценария (пустые строки и комментарии `#` не считаются);
- `--state-vars <имена через запятую>` — переменные книги для снимка (имена как в книге, без
  `_` экспорта INSTEAD); `*` — все переменные, включая служебные. Без параметра переменных в
  снимке нет. Несуществующие имена пропускаются;
- `--deterministic[=N]` — воспроизводимая случайность, как у `nlb_main`: k-й rnd(n) даёт
  (k mod n) + 1, SHUFFLE разворачивает список, N — начало счётчика (по умолчанию 0). Для маршрутов
  книг с RND/SHUFFLE (Frontier): без него снимки двух прогонов одного сценария расходятся.

Если файл `--state-log` не открывается, сценарий не выполняется: nlb_sdl завершается с кодом 2
(как при невыполненной команде) — тест не пройдёт молча без диагностики.

Проверка файла: `python3 tools/check_state_log.py state.jsonl [--commands N]` — каждая строка —
JSON с обязательными полями нужных типов, `index` подряд с 0, `screen` из допустимых
(`finished` — только при `finished` = true; `finished` = `model.finished`),
`portion.index` в пределах `count`, `model.pageId` = `pageId`; с `--commands N` — ровно N + 1
записей. Раннеру тестов стоит вызывать её после каждого прогона: новое поле `ScreenModel`,
забытое в сериализаторе, не сломает её, а пропавшее обязательное — сломает.

## Запись (schema 1)

| поле | что это |
|---|---|
| `schema` | версия формата, сейчас 1 |
| `index` | номер команды сценария, с 1; 0 — состояние до первой команды |
| `command` | строка команды как в сценарии |
| `ok` | команда выполнена (то же, что отсутствие `[НЕ ВЫПОЛНЕНО]` в выводе) |
| `pageId` | UUID текущей страницы (`PlayerEngine::screen().pageId`) |
| `screen` | что **на экране** (не свойство страницы): `page` — текст страницы (и текст концовки, пока его читают); `choices` — открыт экран вариантов; `message` — сообщение (конец игры без картинки «Конец» в теме, внешняя игра, ошибка); `finished` — показан экран конца VN («Конец» и «Попробовать ещё раз», `GameScreen::endScreenShown`) |
| `finished` | ходов больше нет — конец игры (= `model.finished`, `PlayerEngine::isFinished`). На VN-концовке — уже с первой порции, когда `screen` ещё `page` |
| `portion.index`, `portion.count` | номер показанной порции текста VN (с 0) и число порций. **Только в режиме экрана вариантов VN**: в STANDARD и при вариантах в тексте порций нет, `count` = 0, `index` = 0, `visible` пуст — это не ошибка, текст тогда — в `model` (`pageText`, `reactionText`) |
| `portion.more` | после показанной есть ещё порции |
| `portion.visible` | текст показанной порции: абзацы `{runs: [{kind, text, target}], joinPrevious}` |
| `variables` | `{имя: значение}` из `--state-vars`: число, логическое, строка или `null` (и для нечислового вещественного: nan, inf) |
| `model` | `ScreenModel` целиком (`nlb/presentation/ScreenModelJson.h`): `pageText`, `reactionText`, `choices` (`index`, `text`, `enabled`, `trivial`, `inlineLink`, `altText`), `inventory`, `sceneObjects`, `pageImage`, `style`, `finished`… |

Текст в снимке — исходный текст книги, до типографских замен: их делает только отрисовка
(`GameScreen.cpp`: `dashes`, `quotes`), как модули `dash` и `quotes` экспорта в INSTEAD. В трассе
INSTEAD текст уже заменён, поэтому при сравнении это нормализация, а не расхождение. Замены
(в `portion.visible`, `model.pageText`, `model.choices[].text` и `altText` их ещё нет):
- `--` между не-дефисами -> «—» (`---` не трогается);
- `_"` -> «, `"_` -> », `"текст"` -> «текст», `,,` -> „, `''` -> ”.

Номер варианта («1. », «2. » — по доступным вариантам) тоже добавляет только отрисовка: в
`model.choices[].text` его нет. Поэтому `text_contains` в маршрутах — по фрагментам без `--` и
кавычек, а `choices_contains` — без номеров.

### Концовка: `screen` и `finished`
`screen` — состояние экрана, `finished` — свойство игры. На концовке VN (страница без ссылок)
`finished` = true с первой порции, но игрок ещё читает текст: `screen` — `page`, как
`screen_kind` "page" в трассе INSTEAD, и текст концовки сравнивается с INSTEAD по порциям.
`screen` = `finished` — только после последней порции, когда открыт экран конца
(`GameScreen::showGameOver` -> `m_endScreen`). В экспорте в INSTEAD это комната
`v_<id>_choices` с `_try_again` — в трассе `choices` на той же странице; сравнитель
(`run_route.py`, `same_end_screen`) считает их одним экраном только при той же странице и
`finished` = true, `finished` против `page` INSTEAD — ошибка (экран конца раньше времени).
Пример (wolfman, page42, 8 порций): `page`/true на порциях 0…7, затем `finished`/true на 7 —
INSTEAD: `page` 0…7, затем `choices` 7.

До этой правки `screen` был `finished` уже на первой порции концовки (по `ScreenModel::finished`) —
маршруты, ожидавшие так `expect.screen` "finished" на тексте концовки, ждут теперь `page` и
`expect.finished` true. В маршрутах `expect.finished` (true/false) проверяется по полю `finished`
(только NLBNavigator).

## Команда `settle:<мс>`

`wait:<мс>` после ожидания обновляет сессию (`Session::refresh`, `GameScreen::afterCommand`) — это
закрывает открытый экран вариантов. `settle:<мс>` ждёт так же (анимации идут по часам), но без
обновления: им можно дать кадру успокоиться между действием и `shot:`, не меняя состояния.

## Команда `advance-until:<условие>,<щелчков>,<x>,<y>`

Щёлкать в точке (x, y) экрана 1920×1080, пока не выполнится условие, но не больше заданного числа
щелчков. Если условие выполнено сразу, щелчков нет. Условия:
- `choices` — открыт экран вариантов VN;
- `page_end` — показана последняя порция страницы (или экран уже не страница, или страница
  сменилась);
- `page_change` — другая страница.

Каждый щелчок — обычная команда `click:<x>,<y>` со своей записью state-log; затем — запись самой
`advance-until:` (`ok` — условие выполнено; не выполнено — `[НЕ ВЫПОЛНЕНО]`). Поэтому записей
больше, чем строк сценария: `tools/check_state_log.py --min-commands N`. Как `click:`, команда не
обновляет сессию — иначе закрылся бы экран вариантов, до которого листали. Ей пользуется действие
маршрутов `advance_until` раннера дифференциальных тестов (`tests/differential/run_route.py`):
NLBNavigator листает сам, не по числу щелчков из прогона INSTEAD.

## Команда `clickchoice:text=<фрагмент>`

Как `clickchoice:<N>`, но вариант — по фрагменту текста: доступный вариант, в исходном тексте
которого (`model.choices[].text`, до типографики и без номера) есть фрагмент; такой должен быть
ровно один, иначе `[НЕ ВЫПОЛНЕНО]`. Ей пользуется действие маршрутов `choose` раннера
дифференциальных тестов: номер варианта заранее неизвестен, а сценарий `nlb_sdl` составляется до
прогона.

## Команды `give:<объект>` и `drag:<x>,<y>,<dy>`

`give:<имя объекта>` кладёт объект в инвентарь (`PlayerEngine::giveItem`) — так можно сразу
проверить отрисовку предмета, не проходя книгу до него («Фронтир»: карта в бою, `give:common25`).
`drag:<x>,<y>,<dy>` — перетаскивание левой кнопкой: нажать в точке (x, y) экрана 1920×1080,
сдвинуть мышь на dy пикселей по вертикали и отпустить. В окне текста это плавная прокрутка, как в
INSTEAD (`GameScreen::press`/`mouseMove`/`release`); без движения — обычный щелчок при отпускании.
