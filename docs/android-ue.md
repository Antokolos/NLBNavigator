# Unreal для Android: Meta Quest и телефон

Один проект — две сборки, `tools/ue/package_android.ps1`:

```
powershell -ExecutionPolicy Bypass -File tools\ue\package_android.ps1 -Target phone
powershell -ExecutionPolicy Bypass -File tools\ue\package_android.ps1 -Target quest
```
(`-Config Shipping` — для выпуска; `-Engine <каталог движка>` или переменная `UE_ROOT`.)

- **quest** — как настроено в проекте: OpenXR, пакет для Meta Quest (`bPackageForMetaQuest`),
  только VR.
- **phone** — на время упаковки выключены OpenXR и пометки Quest; файлы проекта потом
  возвращаются. В игре без системы XR включается обычный режим.

Режим выбирается в игре сам: на Android VR — если есть система XR (сборка quest), иначе —
обычный режим с экранным управлением.

## Экранное управление (телефон)
- слева внизу — джойстик ходьбы, справа — обзора (стики геймпада: IA_Move, IA_Look);
- кнопки: «Меню» (пауза) слева вверху; справа — «Действие» (взаимодействие с предметом,
  открыть книгу), «Прыжок», «Огонь» (только с оружием в руках);
- в книге — кнопка «← В игру»; меню книги — её собственная кнопка справа вверху; касания по
  тексту и ссылкам — как щелчки мышью;
- в VR и в меню паузы экранного управления нет.

Проверить на ПК: запустить игру с ключом `-touch` (или включить «Always Show Touch Interface»
в настройках ввода) — в редакторе касания эмулирует мышь.

## Если игра упала на телефоне
```
powershell -ExecutionPolicy Bypass -File tools\ue\symbolize_android_crash.ps1 -Capture
```
Скрипт сам снимает журнал с подключённого телефона (`adb logcat -d`), находит в нём ошибку и
стек, берёт из `out\` библиотеку с символами от той же сборки (по Build ID) и печатает стек с
функциями, файлами и строками. Уже снятый журнал: `... symbolize_android_crash.ps1 phone.txt`
(подойдёт и файл журнала игры `NLBNavigator.log` из
`Android/data/com.nlbhub.NLBNavigator/files/UnrealGame/NLBNavigator/NLBNavigator/Saved/Logs`).
Символы есть только у сборок, собранных на этой машине и ещё не перезаписанных следующей.

## Аллокатор на Android
На Android и iOS игра использует системный аллокатор (`StaticAllocator = Ansi` в
`NLBNavigator.Target.cs`): плеер книг и libc++ собраны в игру статически, и с аллокатором
движка (Binned3) память, выделенную внутри libc++, освобождал бы чужой аллокатор.

## Подводные камни (найдены на устройствах — не «исправлять» обратно)
Каждый пункт стоил отладки на телефоне или шлеме; прежде чем менять это место, перечитайте.

**Сборка и запуск на Android**
- **Аллокатор.** Падение «FMallocBinned … unrecognized pointer» (при загрузке библиотеки, при
  открытии книги) — память libc++ освобождал аллокатор движка. Лечится только
  `StaticAllocator = Ansi` в `NLBNavigator.Target.cs`; с собранным (установленным) движком к нему
  нужен `bOverrideBuildEnvironment = true`, иначе UBT отказывается собирать. Дополнительно в
  модуле `NLBPlayer` — `_LIBCPP_DISABLE_EXTERN_TEMPLATE` и никаких тяжёлых статических объектов в
  ядре (`NullObj` — при первом обращении).
- **Метки указателей** Android 11+ — `ExtraApplicationNodeTags=android:allowNativeHeapPointerTagging="false"`
  в `DefaultEngine.ini`.
- **Книга в APK** — только из `Content/NLBFiles` (скрипт упаковки копирует её туда сам).
- **Телефонная сборка** — без OpenXR, без пометок Quest, без `vr.MobileMultiView` и
  `vr.InstancedStereo` (иначе чёрная сцена), с запасным OpenGL ES; всё это делает
  `package_android.ps1 -Target phone` на время упаковки.
- **«Cook failed» за пару секунд** — устарели модули редактора (после `git merge main`); скрипт
  собирает их перед упаковкой.

**Касания (телефон)**
- Пока палец прижат, Slate присылает и движения «курсора мыши», стоящего там, где был прошлый
  палец. Экран книги принимает движения **только своего касания** (`IsTouchEvent` и тот же номер
  указателя) — иначе нажатие превращалось в перетаскивание и щелчок по «Далее» терялся.
- Порог перетаскивания: мышь — 8 точек, палец — 96; касание мимо ссылки засчитывается ближайшей
  ссылке в пределах 96 точек. В журнал пишется `NLB: касание — …` с областями рядом.

**VR (Quest)**
- Экран книги на панели — видимость `Visible` (у `UUserWidget` по умолчанию
  `SelfHitTestInvisible`, луч проходил насквозь), без прокрутки перетаскиванием (дрожь луча).
- Луч и указатель — от позы **прицела** `RightAim`, не хвата `Right` (у Quest она наклонена
  вверх).
- **Подсказка над предметом** — отдельный `UWidgetComponent`, созданный **сразу в World space до
  `RegisterComponent`** (как панель книги). Экранный виджет, переключённый в World на ходу
  (`SetWidgetSpace`), в шлеме не рисуется. Ставится в 60 см от **камеры персонажа** (у
  `PlayerCameraManager` в VR место без смещения шлема) на линии к предмету, размер в поле
  зрения постоянный (`VRPromptScale` при `VRPromptDistance`).
- Подсказка по устройству: ПК — клавиша действия из раскладки ввода, телефон — «Действие»,
  VR — «Курок».
