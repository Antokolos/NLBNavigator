## 2. Оценка «сколько осталось»

При нынешнем способе (маршруты пишутся вручную, каждая правка проверяется полным прогоном CI):

- **`wolfman` до конца** (оставшиеся 12 страниц и 7 концовок, полиция, английская версия,
  достижения): ещё **4–7 дней**.
- **Остальные пять книг**: раннер пока умеет только `capture`, `key`, `click`, `advance`,
  `select_choice`. Для «Слуги Ра» (STANDARD: объекты, инвентарь, применение), «Варвара»
  (выбор навыков объектами, внешняя игра), «Шапочки» (хаб, внешние модули в три уровня,
  достижения) нужны новые действия и проверки. «Фронтир» (431 страница, 2838 картинок) вручную
  полностью не покрыть никогда.
  По темпу `wolfman` это **2–3 месяца**, причём полное покрытие всех ветвей «Фронтира» так и не
  будет достигнуто.

Вывод: работу нужно не продолжать «как есть», а **ограничить по объёму и ускорить** (ниже).

## 3. Что тормозит

1. **Один прогон CI — час, и он упрётся в потолок.** Всё идёт одним job'ом (52 шага), время
   растёт с каждым маршрутом; `timeout-minutes: 90`, а прогоны уже 76 минут — ещё 2–3 маршрута,
   и CI начнёт падать по таймауту.
2. **`concurrency: cancel-in-progress: true`** — каждый новый push отменяет идущий часовой
   прогон: отсюда 26 отменённых. Работа сделана, результат выброшен.
3. **Маршруты хрупкие.** В них координаты щелчков и число продвижений отдельно для каждого
   движка. Любая разница в пагинации (как #37: 15 против 17 порций) сдвигает все следующие
   шаги, и падает весь хвост маршрута — так и было.
4. **Каждая ветка — отдельный маршрут с начала игры**: общий префикс (титул → забор →
   грабитель → бар) проигрывается в каждом из 15 маршрутов заново.
5. **Ничего не в main.** 17 831 строка в 29 файлах живёт только в ветке.

### 3.1. Что показал прогон 140 (run id 42406000322)

- Прошли сборка, общий маршрут и все маршруты `wolfman`, включая семь маршрутов через
  страницу 8 с новыми ожиданиями после перегенерации эталона (#37: 16 продвижений, 17 порций
  в обоих движках).
- Упал **последний** шаг, «Run wolfman police branch in INSTEAD», через 1 ч 17 мин после
  старта. Причина — ошибка в самом маршруте `wolfman-police-hospital-corpse.json`: пропущен
  шаг `opening-choices` (листание до экрана вариантов, `advance` 9/9, как во всех остальных
  маршрутах). Шаг 4 ссылается на несуществующий `visual_change_from: opening-choices` и
  выбирает вариант на 2-й порции из 10. Так же падал прогон 139.
- Отсюда:
  1. шаг «Validate differential test definitions» проверяет только синтаксис JSON
     (`json.tool`), а ошибки структуры маршрута — ссылки на несуществующие шаги, выбор без
     экрана вариантов — находятся только через час;
  2. исследовательский маршрут делает красным весь прогон, хотя остальные 14 маршрутов
     зелёные — по статусу прогона этого не видно;
  3. новый маршрут добавлен в конец последовательности, поэтому его ошибка видна последней.

## 4. Рекомендации

### 4.1. Слить в main сейчас (не ждать полного покрытия)

- **Закрыть #25** как устаревший: #32 содержит всё из него, а вывод `[screen]` из
  `Source/NLBSdl` заменён на `--state-log`, который уже в main.
- **Слить #32 в main.** Сливается без конфликтов (проверено). Код плеера он не трогает: только
  `tests/differential/**`, workflow, `README.md` и 5 строк `CMakeLists.txt` (поиск ZLIB для
  SDL3_image/ttf). Workflow запускается только вручную и при push в ветки `ci/*`, так что на
  разработку в main не повлияет.
- Перед слиянием убрать из `tests/differential/` переписку агентов (`CLAUDE_CODE_ANSWERS.md`,
  `CLAUDE_CODE_REPLY_2.md`, `CLAUDE_CODE_REVIEW.md`, `INDEPENDENT_REVIEW_CLAUDE.md`) — в
  комментарии к #28 или в `docs/archive/`. В main оставить `README.md` (как запускать),
  `WOLFMAN_BRANCH_MAP.md` (карта ветвей) и краткий `TESTING_PROGRESS.md`.
- Дальше работать короткими PR в main: «маршрут X», «действие Y в раннере».

### 4.2. Ускорить CI (сделать до новых маршрутов)

1. **Матрица по маршрутам**: job «build» один раз собирает `nlb_sdl` и выкладывает artifact;
   job «route» (`strategy.matrix.route`) — по маршруту на job, INSTEAD + NLBNavigator + сравнение.
   15 маршрутов идут параллельно: **≈15–20 минут вместо часа**, и таймаут больше не грозит.
2. **Кэш vcpkg/SDL3** (`actions/cache` по хэшу `vcpkg.json`/версии) — сборка из минут в секунды.
3. **`cancel-in-progress: false`** (или группа по маршруту) — не выбрасывать почти готовые прогоны.
4. **На push — только изменённые маршруты** (по `git diff` списка `routes/*.json`), полный набор —
   вручную и по расписанию (раз в сутки).
5. **Статическая проверка маршрутов за секунды** (`run_route.py --check` или
   `validate_catalog.py`): уникальные id шагов, `visual_change_from` ссылается на шаг выше,
   перед `select_choice` есть шаг, который ведёт к экрану вариантов, последовательные
   `portion_index` на одной странице, `portion_count` одинаков на странице. Запускать в
   первом шаге CI и локально перед push.
6. **Исследовательские маршруты** — с пометкой в JSON (`"status": "exploratory"`) и в
   отдельном job с `continue-on-error: true`: их падение видно, но не красит основной прогон.
7. **Новые и изменённые маршруты — первыми** (или локально: INSTEAD ставится из пакета
   `instead`, маршрут проходит за 1–5 минут под `xvfb-run`; нужны `openbox`, `xdotool`,
   `x11-utils`).

### 4.3. Сделать маршруты устойчивыми

1. **Не считать продвижения вручную.** Действия «листать до последней порции» и «листать до
   экрана вариантов» (по state-log и trace INSTEAD) вместо `clicks: {instead: 14,
   nlbnavigator: 16}`. Тогда различие в числе порций — **отдельная проверка** (сравнить
   `portion_count`), а не каскад ошибок по всему маршруту.
2. **Выбор варианта — по тексту**, а не по координатам: `select_choice: {text: "Съесть грабителя"}`.
3. **Общие префиксы**: маршрут описывается как ветвь от именованной точки («после бара»);
   раннер либо проигрывает префикс один раз за job, либо использует сохранение (в INSTEAD и в
   NLBNavigator оно есть).

### 4.4. Покрытие — считать автоматически

- **Отчёт покрытия** в artifact: страницы и концовки книги (из каталога книги) против страниц,
  встреченных в маршрутах. Для `wolfman` сейчас 42/54 и 9/16 — это и есть мера готовности.
- **Поиск ветвей — машиной, не руками**: обход дерева выборов консольным плеером (`nlb_main`
  или Java `ConsolePlayer` с `--deterministic`) — он за секунды даёт все достижимые пути.
  В INSTEAD проигрывать только выборку: по одному пути на каждую концовку и на каждую
  механику.

Предлагаю зафиксировать в #28 вместо «все ветви всех книг»:

Новые действия раннера (объекты, инвентарь, применение) — отдельными PR до соответствующих книг.

### 4.6. Разделение работы

- Тестирование (маршруты, раннер, CI) — ChatGPT, в ветках `ci/*` с PR в main.
- Найденное расхождение — **отдельная задача** с минимальным воспроизведением (как #37:
  страница, оба движка, ожидание, доказательство). Решение «что считать правильным» — за
  владельцем; исправление движка, экспорта или эталона — Claude в main.
- Тесты не меняют код плеера (правило #28, п. 7) — это уже соблюдается.
