## 2. Замечания по Windows-драйверу

### 2.1. Выбор окна

- Окно ищется только среди видимых окон **PID запущенного процесса** (`GetWindowThreadProcessId`
  == pid), выбирается самое большое по клиентской площади; чужое окно выбрать нельзя.
- Ожидание появления — до 20 с с опросом, при завершении процесса раньше окна — ошибка с
  указанием `session.log`.
- Пересоздание окна не поддерживается сценариями маршрутов (INSTEAD не пересоздаёт окно при
  save/load); при закрытии процесса раннер завершает шаг с ошибкой, а не продолжает молча.

### 2.2. Ввод

- Поддержаны `space`, `escape`, `enter`, `tab`, `backspace`, стрелки, `home/end`,
  `pageup/pagedown`, цифры, латинские буквы и `F1–F12` (включая F2/F3/F5/F8/F9).
- Модификаторы клавиш маршрутами не используются; отдельной эмуляции Ctrl/Alt/Shift нет —
  при появлении таких шагов потребуется расширение.
- Координаты — клиентская область (`GetClientRect` + `ClientToScreen`); рамка окна не влияет.
- DPI: процесс объявляет per-monitor awareness; координаты и снимок — в физических пикселях.
  Проверено при 100%; 125/150% — известное ограничение (окно должно оставаться 1920×1080 в
  физических пикселях).
- Последовательность: keydown → 50 мс → keyup; клик: move → buttondown → 50 мс → buttonup.
- **Это оконные сообщения, а не физический ввод.** SDL2 обрабатывает их в своей оконной
  процедуре, и для маршрутов поведение совпало (22/22), но глобальные хуки и низкоуровневые
  события не эмулируются. Утверждение о полной эквивалентности не делается.

### 2.3. Скриншоты

`PIL.ImageGrab` снимает область экрана по клиентской геометрии. Если окно активно и не
перекрыто — кадр корректный (проверено на 22 маршрутах). При перекрытии другим окном или
сворачивании будет снят чужой кадр; это **документированное ограничение**: сравнение сразу
покажет расхождение, молчаливого принятия нет (кадр сравнивается с другим движком). Захват
через PrintWindow для SDL/OpenGL не используется.

### 2.4. Изоляция данных

- `nlb_sdl` на Windows берёт домашний каталог из `USERPROFILE` (`PlatformPaths::homeDir`), поэтому
  раннер выставляет `USERPROFILE`, `APPDATA`, `LOCALAPPDATA` в `nlbnavigator-home` каталога
  прогона. Проверено: `wolfman.saves` появляется внутри прогона, реальный профиль не затрагивается.
- INSTEAD получает `-appdata` внутри прогона, `HOME`/`USERPROFILE` также изолированы.
- Каждый сценарий стартует с чистого каталога; при перезапуске переносится только файл слота,
  переданный через `--seed-home`.

### 2.5. Junction и файловые операции

- Каталоги overlay создаются junction (`mklink /J`), если symlink недоступен.
- Удаление overlay сначала удаляет junction через `os.rmdir`, не заходя внутрь; исходные
  игровые данные не изменяются.
- Повторный запуск удаляет прежний overlay и создаёт новый; уже существующие пути
  обрабатываются; запись в закреплённые данные отсутствует.

### 2.6. Завершение процессов

- Перед `terminate()` отправляется `WM_CLOSE`; ожидание до 5 с, затем `terminate()`, затем
  `kill()` при необходимости.
- Проверено на save/load: слот сохраняется и читается новым процессом; trace сбрасывается;
  INSTEAD завершается штатно. Для сценариев аварийного выключения принудительное завершение
  остаётся доступным.

### 2.7. Совместимость с Linux

- `win_gui` импортируется только при `sys.platform == "win32"`; Linux-путь (Xvfb, openbox,
  xdotool, ImageMagick) не изменён.
- Форматы `state-log`, `route-report`, trace и сравнения не менялись; Linux-тесты не
  затронуты.
